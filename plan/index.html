Sales Agent: fork plan

Fork the creator outreach engine into a self-hosted sales agent that runs many campaigns, each with its own brief, audience, rules and guardrails. Sold as a one-time bundle first, built so it can become SaaS later without a rewrite. Brevo runs the first instance.

1. Principles

Campaign is the unit

Everything a user configures lives on a campaign. Many campaigns run at once. Only suppression, mailboxes and the do-not-contact list are global.

Pay as you go

Setup costs under $10. After that the buyer pays Cloudflare and their model provider only for what runs. No paid data or verification APIs required; paid data keys are optional plug-ins.

Lift, don't copy

The engine's 13k-line index.js does not come across. We lift proven modules by name into a slim new Worker.

SaaS-ready, not SaaS

A workspace_id on every row and every secret, no hardcoded config. Nothing else multi-tenant gets built now.

3. Feature set (v1)

A. Campaigns

  • Create via wizard, from URL
  • Many campaigns live at once
  • Pause, resume, clone, archive
  • Brief versions with diff (from campaign_brief_versions)

B. Lead engine (free)

  • Sources: hiring-platform job feeds, OpenStreetMap, company registries, Common Crawl, directory pages, CSV
  • Crawl site: home, about, team, contact
  • Model extracts people, roles, emails, hooks
  • Email finding: published, then domain pattern, then guess
  • Free verification: syntax, MX via DNS-over-HTTPS, disposable and role lists, catch-all flag
  • Fit score with reason, disqualify with reason
  • Dedupe across campaigns

C. Outreach

  • First email grounded in crawled facts
  • Fact-check: no claim not in brief or ticked proof
  • Quality gates: salutation match, banned copy, no dashes, length
  • Send via Gmail API, threaded
  • Caps, ramp, send window, jitter
  • Published emails go first, guesses only after the domain proves out

D. Conversations

  • Poll Gmail, match to lead
  • Classify: interested, question, objection, not now, no, out of office, unsubscribe, bounce
  • Draft reply from brief and FAQ only
  • Concessions inside ceiling, else hand off
  • Booking: offer 3 free slots, create invite on confirm, or send booking link

E. Follow-up lanes

  • No reply: 3 follow-ups, 2 days apart
  • Went quiet: 3 nudges
  • Not now: wake on the date given
  • No: 2 win-backs, then stop for good
  • Booked: confirm day before, reschedule no-shows
  • One cadence per person, across campaigns

F. Safety

  • Approval queue with edit and approve
  • Emergency stop, per-campaign pause
  • Manual takeover per thread (checked on every send path)
  • Opt-out is permanent, all campaigns
  • Bounce learning: suppress address, fix domain pattern, pause mailbox if bounce rate spikes
  • Daily rule sweep (subtractive only)
  • Incidents list

G. Learning (simple)

  • Every edit or rejection in the approval queue becomes a learned rule for that campaign
  • Segment table: after 50 sends, segments under a reply-rate floor auto-pause; best segment gets more of the daily budget

H. Reporting

  • Per-campaign funnel: found, verified, contacted, replied, interested, won
  • Segment performance and cost per lead
  • Live activity feed
  • Daily digest email
  • CSV export of leads and outcomes

I. Packaging

  • One-command installer
  • Single admin login
  • License key check (install + weekly)
  • One-command updates with schema migrations
  • Setup docs and a 5-minute video

Email note (the one tricky part).
  • Google Workspace: Gmail send and read are "restricted" scopes, so one shared Google app would need Google's security review (a SaaS-stage job). In the bundle each buyer creates their own Internal Google app, guided by 6 screenshots: no review, sign-in never expires.
  • Personal gmail.com: an Internal app isn't possible and a test-mode app's sign-in expires every 7 days, so personal Gmail connects through path 3 (app password over SMTP and IMAP). Needs 2-step verification on the account.
  • Microsoft 365 / Outlook: Microsoft is retiring password-based sending, so it goes through Sign in with Microsoft with the buyer's own app registration (same guided setup, no review for a single organisation).
  • Advice shown in the UI: send cold email from a separate domain, not your main one. Done-for-you setup handles all of this for the buyer.

6. Architecture

Buyer's Cloudflare account ├─ Worker (API + dashboard via static assets + cron every 5 min) │ cron tick ─▶ for each live campaign: │ source ▶ crawl ▶ find email ▶ verify ▶ fit ▶ draft ▶ gates ▶ approve? ▶ send │ poll Gmail ▶ classify ▶ reply / book / hand off / suppress │ lanes due ▶ follow-ups daily 02:00 ▶ rule sweep + digest ├─ D1 (all state, workspace_id on every table) └─ Workers AI (default model) Google APIs (Gmail, Calendar) optional: other model / data keys
  • One Worker, one database, one cron. No queues, no KV, no Durable Objects in v1. The cron does small batches each tick; the engine already works this way.
  • Secrets: refresh tokens and API keys stored in D1, encrypted with a key set at install time as a Worker secret.
  • Auth: one admin password, signed session cookie.
  • Cost, pay as you go: setup under $10 (Workers Paid $5 for crawling CPU, plus optional model credit). After that the buyer pays Cloudflare and their model provider only for usage; D1 and Workers AI at this volume mostly fit inside included limits.

10. Deliberately not in v1

  • LinkedIn, X, Instagram channels; Instantly; Tolt; fee pricing
  • Multi-user, roles, teams; SaaS billing; hosted multi-tenant
  • CRM sync (CSV export covers it; HubSpot later)
  • Mailbox rotation and pooled warm inboxes (SaaS feature)
  • A/B test framework beyond segment auto-pause
  • File uploads for context (paste text instead)

Free sourcing yields too few leads for some nichesSpike first. Bring-your-own CSV and optional data keys as the valve. Niche-specific sources added as small plug-ins
Bounces damage the buyer's domainPublished emails first, guesses only after a domain proves its pattern, low caps with ramp, auto-pause a mailbox above a bounce threshold, advise a separate sending domain
Email connection frictionGuided setup per provider with screenshots and a Test button; app-password path for anything without OAuth; done-for-you does it for them; SaaS later uses one verified Google and Microsoft app
Free model quality for writingPer-task model choice; writing task can point at a better free-tier key; fact-check and gates stay deterministic
