QA + SECURITY + UI PLAN v17 Nov 2026ClosefastIN PROGRESS

Use Closefast like a real customer, find what breaks, test for data leaks, and make it feel modern

Farooq asked for four things on 7 Nov: a full walk through every user journey, from onboarding to each use case; a bug log to plan fixes from; a separate data-leak and security test; and a UI that's more modern, less wordy, and written like a friendly human.

How it runs

  1. UI refresh and security audit, in parallel. The UI work only touches the browser files. The security work only touches the server and tests.
  2. Journey walk-through on the refreshed UI. It runs on a local copy of the app (local database, test accounts), never on production data. Nothing is ever emailed to a real person: sending stops at Approvals, or goes to a local mail catcher.
  3. Fix policy: data leaks and anything critical get fixed straight away. Everything else is logged first, then fixed in one batch, so fixes don't tangle with the walk-through.
  4. Deploy, then recheck the main journeys on the live app (read-only on production).

UI refresh

  • Look: cleaner type scale, more white space but tighter content, softer cards, clear primary buttons, consistent pills and tables, good at phone width, in both light and dark.
  • Words: every page gets a short title and at most one line of help. Buttons are verbs. Empty states say what to do next. Contractions, short sentences, no jargon, no dashes.
  • Voice: friendly and human ("Nice, 12 new people are ready to start"), never cute, and never vague about money or sending.
  • Home: four tiles that matter (Not started, In outreach, Replies, Meetings), plus one "next step" card.

Security and data-leak tests

Built from the OWASP API Security Top 10 (2023), OWASP ASVS level 2 controls, and the OWASP Top 10 for LLM apps (2025), applied to a multi-tenant SaaS that reads strangers' text (LinkedIn posts, websites, email replies) and sends email.

AreaWhat we test
Tenant isolationEvery route called as workspace B using workspace A's ids (leads, campaigns, messages, sources, watches, meetings, exports). A static check that every query on tenant tables filters by workspace.
Auth and sessionsRoutes without a session, expired or forged cookies, cookie flags, password reset tokens, account enumeration, ops token only on admin routes.
Secrets and data exposureNo inbox passwords, API keys, tokens or our data costs in any response, event, export or log. Locked people stay hidden until paid.
Stored XSSNames, titles, companies, post quotes, CSV fields, email replies and brief text containing HTML or script, rendered on every page.
InjectionSQL built from strings, CSV formula injection in exports, email header injection (names with line breaks).
SSRFWebsite crawl, booking-link check, public URL, inbox host settings pointed at localhost, internal IPs and metadata addresses.
Prompt injection and LLM leaksEmail replies, websites and posts that tell the agent to reveal other prospects, the brief, keys or system prompts, or to email someone else. Support chat asked for other workspaces' data.
Abuse and costRate limits on signup, login, estimates, support chat, password reset and imports. Huge CSVs and payloads.
MoneyCharging twice, negative quantities, buying past a balance, webhook signature checks, refund paths.
Email safetyUnsubscribe links that can't be forged, opt-outs honoured across campaigns, test mode never reaching prospects.
Headers and configCSP, frame protection, HSTS, CORS, error messages that leak internals, and npm audit.

The output is an automated test suite that stays in the repo and runs on every change, plus a findings list with severity, proof and fix.
